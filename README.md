新增菜品修改功能（含回显）：提供 GET /admin/dish/{id} 回显接口和 PUT /admin/dish 修改接口；回显时 Service 先按 id 查 dish 表拿到菜品、再按 dish_id 查 dish_flavor 表拿到口味列表，用 BeanUtils 把菜品属性拷贝到 DishVO 并塞入口味集合后返回给前端填表；修改时 updateDishWithFlavor 加 @Transactional，把"更新菜品 + 替换口味"放进同一个事务——先用 DishMapper.updateDish 更新菜品（该方法带 @AutoFill(OperationType.UPDATE)，自动填充 update_time/update_user），XML 用 `<set>` 配合 `<if>` 只更新前端传了值的字段，再按 dish_id 删除该菜品的全部旧口味、给新口味逐条补上菜品 id 后批量插入，用"删除重建"实现口味的整体替换，避免逐条比对新旧口味的复杂度

新增菜品起售停售与按分类查询接口：POST /admin/dish/status/{status}?id= 用于列表页的开关，status 走路径变量、id 走查询参数，Service 用 Dish.builder().id(id).status(status).build() 构造只含 id 和 status 的对象，复用 DishMapper.updateDish 的部分更新能力，只改售卖状态并自动更新修改时间/修改人，其他字段一个都不碰，因此没有复用会重建口味的修改接口；GET /admin/dish/list?categoryId= 供套餐模块选择菜品时使用，查询 dish 表中该分类下 status = 1（起售中）的菜品，返回 List<Dish> 实体（不需要跨表拼装）
