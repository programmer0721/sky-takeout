微信登录功能：只有一个接口 POST /user/user/login，请求体 UserLoginDTO 里就一个 code，返回 UserLoginVO（id、openid、token），对应小程序端 wx.login 拿到 code 直接丢给后端这种流程；UserServiceImpl.wxlogin 先把 appid、secret、js_code、grant_type 拼成参数，用 HttpClientUtil.doGet 请求微信的 https://api.weixin.qq.com/sns/jscode2session 换 openid，openid 为空就直接抛 LoginFailedException(MessageConstant.LOGIN_FAILED)，然后拿 openid 去 user 表查，查不到说明是新用户——用 User.builder() 只塞 openid 和 createTime 再 insertUser，注册和登录合并在一个接口里，不用单独做注册；UserMapper 里 getUserByOpenId 用 @Select 注解直接写 SQL，insertUser 放在 XML 里并带上 useGeneratedKeys="true" keyProperty="id" 把自增主键回填到实体，否则新注册用户返回的 id 会是 null；登录成功后 UserController 把 userId 作为 claim 生成 JWT，签名密钥和过期时间读 sky.jwt 下的 user-secret-key、user-ttl，请求头名称 user-token-name 配成 authentication，所以用户端带的是 authentication 而不是管理端的 token；WebMvcConfiguration 里注册了新的 JwtTokenUserInterceptor 拦截 /user/**，放行 /user/user/login 和 /user/shop/status（打烊状态不登录也要能看），拦截器解析出 userId 后写进 BaseContext，业务代码里 BaseContext.getCurrentId() 就是当前登录用户；微信的 appid、secret 挂在 sky.wechat 下，真实值写在 application-dev.yml，application.yml 里只留 ${sky.wechat.*} 占位再引用一次，和数据库、Redis、阿里 OSS 的配置套路保持一致
